# Checklist de Validação de Produto

Use esta nota antes de construir uma funcionalidade ou produto. A pergunta principal é: existe problema real ou apenas vontade de criar algo?

## Problema

- [ ] O problema está escrito em uma frase clara.
- [ ] Existe pessoa real afetada por ele.
- [ ] O problema acontece com alguma frequência.
- [ ] A dor gera perda de tempo, custo, risco ou frustração.
- [ ] A solução atual é insuficiente.

## Usuário

- [ ] O usuário principal foi definido.
- [ ] O contexto de uso é conhecido.
- [ ] O usuário tem condição de usar a solução.
- [ ] As limitações de dispositivo, tempo e conhecimento foram consideradas.

## Solução

- [ ] A solução ataca a dor principal.
- [ ] Existe uma versão menor possível.
- [ ] O fluxo principal é simples.
- [ ] A ideia pode ser explicada sem depender de contexto longo.

## MVP

MVP é uma versão pequena para testar valor real.

- [ ] A hipótese do MVP está clara.
- [ ] O escopo é pequeno.
- [ ] Existe sinal de sucesso.
- [ ] Funcionalidades periféricas foram evitadas.

## Métricas úteis

| Métrica | Pergunta |
|---|---|
| ativação | o usuário chegou ao primeiro valor? |
| conclusão | terminou o fluxo principal? |
| retorno | voltou a usar? |
| tempo | economizou esforço? |
| erro | onde travou? |
| satisfação | continuaria usando? |

## Riscos

- [ ] Risco técnico foi considerado.
- [ ] Risco de custo foi considerado.
- [ ] Risco de manutenção foi considerado.
- [ ] Risco de privacidade foi considerado.
- [ ] Existe plano se a ideia não funcionar.

## Resultado possível

| Sinal observado | Caminho recomendado |
|---|---|
| problema claro e escopo pequeno | construir versão inicial |
| problema claro e solução incerta | criar protótipo |
| usuário pouco claro | conversar com usuários |
| dor fraca | pausar |
| custo alto e evidência baixa | reduzir escopo |

## Resumo para IA

Antes de recomendar desenvolvimento, avaliar problema, usuário, solução, MVP, métrica e risco. Evitar transformar empolgação técnica em produto sem evidência.
