# Produto, UX e Validação

Produto não é só software funcionando. Produto é uma solução que resolve um problema real para alguém de forma compreensível, útil e sustentável.

## Perguntas centrais

- Quem usa?
- Qual dor existe?
- O que a pessoa faz hoje para resolver?
- Por que a solução atual é ruim?
- Qual mudança mínima gera valor?
- Como saber se funcionou?

## Diferença entre ideia e produto

| Ideia | Produto |
|---|---|
| desejo abstrato | solução testável |
| foco no criador | foco no usuário |
| muitas funcionalidades | valor principal claro |
| opinião | evidência |

## UX básica

Boa experiência reduz atrito.

Critérios:

- usuário entende onde está;
- sabe o que pode fazer;
- recebe feedback após ação;
- erros são claros;
- fluxo tem poucos passos;
- visual ajuda, não atrapalha;
- sistema respeita contexto real de uso.

## Validação

Validar é testar hipótese antes de investir demais.

Hipóteses comuns:

- usuário tem o problema;
- usuário entende a solução;
- usuário aceita usar;
- usuário aceita pagar ou trocar tempo;
- solução é viável tecnicamente.

## MVP

MVP é a menor versão capaz de testar valor real. Não é produto malfeito, é produto focado.

## Métricas úteis

| Métrica | Mede |
|---|---|
| ativação | usuário chegou ao primeiro valor |
| retenção | usuário voltou |
| conversão | usuário completou ação desejada |
| tempo de tarefa | esforço para concluir fluxo |
| erro | onde usuários travam |
| satisfação | percepção subjetiva |

## Erros comuns

- construir antes de validar;
- adicionar função para compensar falta de clareza;
- ignorar feedback ruim;
- confundir gosto pessoal com UX;
- medir vaidade em vez de valor;
- tentar agradar todo mundo.

## Checklist

- [ ] O problema está claro?
- [ ] O usuário foi definido?
- [ ] Existe hipótese testável?
- [ ] O MVP é pequeno?
- [ ] Há métrica de sucesso?
- [ ] O fluxo principal é simples?
- [ ] Feedback do usuário será registrado?
