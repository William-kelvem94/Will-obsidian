# 🔌 Model Context Protocol (MCP) - O Novo Padrão de Integração

A fundação do Model Context Protocol (MCP), desenvolvida pela Anthropic, resolveu dezenas de debates arquiteturais de uma só vez, propiciando um padrão Cliente-Servidor unificado, stateful, e seguro.

## 1. A Filosofia e a Arquitetura do Protocolo
O MCP inverte a lógica do Function Calling. Em vez de você criar as ferramentas de codificação direto na mesma máquina rodando a IA (o que gera vulnerabilidades graves e viola o Zero Trust), você isola tudo.

### O Triângulo de Execução do MCP
1. **O LLM:** Cérebro na nuvem.
2. **O MCP Client:** Host intermediário.
3. **O MCP Server:** Executor blindado via STDIO.

#### Sampling em MCP e a Negociação de Capacidades de Requisição Contextual Larga

A especificação oficial introduziu os padrões de `Sampling`, que alteram a hierarquia tradicional do LLM orquestrador. Em vez do Orquestrador comandar a Ferramenta cega e local, a Ferramenta Servidor (o seu Script Node ou Python MCP), ao ser chamada com permissões ativadas de Root Capabilities Sampling, pode solicitar explicitamente uma Intervenção LLM na Nuvem do Host de Volta no próprio código via `mcpserver.createMessage()` ou `mcp.sample()`. O Host gera uma inferência menor, injeta no tubo do MCP Subprocesso, o Subprocesso analisa os Logits de Rerank gerados nativamente pelo Sampling Remoto, valida e decide qual a nova query final a passar no Banco Vetorial. Esse Ping-Pong arquitetural tira o encargo das mãos do Agente Geral Clássico ReAct frágil, invertendo os papéis de Roteamento de Grafo, ideal para Sistemas com Lógica Condicional Severa Distribuída de Segurança (Security Bounding Boxes JSON RPC).

#### Segurança da Interface e Tipagem Zod Pydantic Massiva no Schema Protocol

Nenhuma ferramenta local MCP deve confiar no JSON que trafega no Pipe. LLMs (especialmente modelos pequenos < 8B executados em Ollama Local Host via GGUFs como Qwen 2.5) sofrem pesadas Alucinações de Parâmetros (Schema Drift) onde injetam novas strings não contidas ou pulam obrigatórios requeridos (Parameters Mismatch Exceptions). O Validation Payload do `zod` em TypeScript e `pydantic` no Python é acoplado rigorosamente na etapa Early do Middleware. Se o Pydantic joga um `ValidationError`, o MCP Server *não crasheia o pipe do STDIO*, ele encapsula esse Throw numa mensagem RPC com a marcação booleana `isError: true` com a Exceção clara textual e devolve pro LLM. O LLM vê a marcação Vermelha via Host Agent e entra num novo Loop de Reflexão Automática Interna ('Ah, esqueci a aspa no JSON ou errei o enum'), gerando uma Ferramenta corrigida sem arruinar a execução longa e o Terminal do humano local e preservando Integridade Contínua Resiliente do fluxo.

Em vez do Orquestrador comandar a Ferramenta cega e local, a Ferramenta Servidor (o seu Script Node ou Python MCP), ao ser chamada com permissões ativadas de Root Capabilities Sampling, pode solicitar explicitamente uma Intervenção LLM na Nuvem do Host de Volta no próprio código via `mcpserver.createMessage()` ou `mcp.sample()`. O Host gera uma inferência menor, injeta no tubo do MCP Subprocesso, o Subprocesso analisa os Logits de Rerank gerados nativamente pelo Sampling Remoto, valida e decide qual a nova query final a passar no Banco Vetorial. Esse Ping-Pong arquitetural tira o encargo das mãos do Agente Geral Clássico ReAct frágil, invertendo os papéis de Roteamento de Grafo, ideal para Sistemas com Lógica Condicional Severa Distribuída de Segurança (Security Bounding Boxes JSON RPC).

#### Segurança da Interface e Tipagem Zod Pydantic Massiva no Schema Protocol

Nenhuma ferramenta local MCP deve confiar no JSON que trafega no Pipe. LLMs (especialmente modelos pequenos < 8B executados em Ollama Local Host via GGUFs como Qwen 2.5) sofrem pesadas Alucinações de Parâmetros (Schema Drift) onde injetam novas strings não contidas ou pulam obrigatórios requeridos (Parameters Mismatch Exceptions). O Validation Payload do `zod` em TypeScript e `pydantic` no Python é acoplado rigorosamente na etapa Early do Middleware. Se o Pydantic joga um `ValidationError`, o MCP Server *não crasheia o pipe do STDIO*, ele encapsula esse Throw numa mensagem RPC com a marcação booleana `isError: true` com a Exceção clara textual e devolve pro LLM. O LLM vê a marcação Vermelha via Host Agent e entra num novo Loop de Reflexão Automática Interna ('Ah, esqueci a aspa no JSON ou errei o enum'), gerando uma Ferramenta corrigida sem arruinar a execução longa e o Terminal do humano local e preservando Integridade Contínua Resiliente do fluxo.
